# mapac v0.2.0

## 简体中文

MacinDecode APAC Core **v0.2.0** 提供 Windows、Linux 和 macOS 上的 APAC 空间音频解码，
可导出 Float32 WAV／RF64／CAF，查看配置与逐包语法，并比较 PCM。

### 本次更新

- HOA 支持扩展至零至十阶，每个 HOA 系数域最多 121 项，可导出 ACN/SN3D 系数或还源码流声明的源声道。
- SQ、CAC、TNS、共享配置、多 ASC 和 CAF／MP4 快速范围解码使用当前独立实现及登记的数值来源。
- 发行包默认启用 CAC。**遇到活跃 BWE2 帧时返回 `bwe2-unavailable`**，完整解码、快速扫描和内嵌 preroll 均执行该检查。需要 BWE2 数值恢复时，可按开发说明显式提供外部 LSF 输入构建。[可选 BWE2 构建](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/development.md#显式-bwe2-外部输入)
- macOS 27.2 原生参考命令对已核验的高阶 HOA 动态选择失败提供版本限定说明。[原生参考限制](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/support.md#macos-272-原生参考限制)
- 新公开仓库采用独立 Git 历史，数值文件及消费者身份随来源清单核验。三平台压缩包附带全部锁定 Rust 依赖的许可和版权声明。[数值来源](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/source-provenance.md) · [第三方说明](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/THIRD_PARTY.md)

### 第一次解码

解压后进入程序所在目录，把 `input.m4a` 换成自己的 APAC 文件路径。

Windows PowerShell

```powershell
.\mapac.exe --version
.\mapac.exe decode-sq "input.m4a" -o output.wav
```

macOS / Linux

```sh
./mapac --version
./mapac decode-sq "input.m4a" -o output.wav
```

支持含 APAC 音轨的 `.m4a`、`.mp4`、`.caf` 和导出的包目录。
离散布局包括单声道、立体声、5.1、7.1、7.1.4、9.1.6 和 22.2。
WAV／RF64 接受至 7.1.4 的已支持扬声器布局。9.1.6、22.2、HOA 和组合布局使用 CAF。

```sh
./mapac decode-sq "spatial.m4a" -o output.caf
```

输出保持输入采样率和 Float32 精度。CAF 保留原始声道顺序和布局，WAV 使用标准扬声器顺序。
目标文件必须尚不存在。WAV 超过 RIFF 大小限制时自动使用 RF64，也可用 `--format rf64` 指定。
文件导出按块写入，默认不限总大小，可用 `--max-output-mib` 设限。

使用 `--start-frame`、`--frames` 和 `--access fast` 提取片段。
CAF 外部布局标签有误时，可用 `--input-layout 9.1.6` 等选项与 APAC 配置核对并纠正读取解释，报告会记录原始声明。
原有 `--out decoded` 模式输出裸 `pcm.f32le` 和 JSON，默认限额 128 MiB，`-o` 和 `--out` 互斥。[中文上手说明](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/README.md) · [命令行参考](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/commands.md)

### 支持边界

- 输入需包含 APAC 音频。MP4／M4A 支持非分片、单音轨文件，普通 AAC、MP3、FLAC 和加密／DRM 输入会被拒绝。
- CLI 提供音频文件导出。HOA 系数供后续空间渲染使用。
- DRC、响度和 EQ 按元数据解析。解码输出遵循本项目的数值模型，与 AudioToolbox 的对照采用记录的容差。
- LRVQ、外层 ASP 重配置和非零帧长索引会明确报错。各 HOA 模式、布局、采样率和组合流需满足对应配置条件。
- 独立解码使用 `decode-sq`。macOS 的 `decode`、`replay` 等命令调用系统 AudioToolbox 参考后端。[完整支持边界](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/support.md)

反馈问题时请提供程序版本、操作系统、命令和错误提示，提交前去掉个人路径。[Issues](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/issues)

exports Float32 WAV/RF64/CAF, inspects configuration and packet syntax, and compares PCM.

### Your first decode

Open a terminal in the executable directory and replace `input.m4a` with your APAC file path.

Windows PowerShell

```powershell
.\mapac.exe --version
.\mapac.exe decode-sq "input.m4a" -o output.wav
```

macOS / Linux

```sh
./mapac --version
./mapac decode-sq "input.m4a" -o output.wav
```

APAC `.m4a`, `.mp4`, `.caf` and exported packet bundles are supported.
Discrete layouts include mono, stereo, 5.1, 7.1, 7.1.4, 9.1.6 and 22.2.
WAV/RF64 accepts supported speaker layouts through 7.1.4. Use CAF for 9.1.6, 22.2, HOA and composite layouts.

```sh
./mapac decode-sq "spatial.m4a" -o output.caf
```

Output retains the input sample rate and Float32 precision. CAF preserves source channel order and layout, while WAV uses standard speaker order.
The destination must be new. WAV automatically switches to RF64 beyond the RIFF size limit, or use `--format rf64`.
File exports stream in bounded blocks with no default total-size limit. Set one with `--max-output-mib`.

Use `--start-frame`, `--frames` and `--access fast` for excerpts. An option such as `--input-layout 9.1.6`
checks an incorrect CAF layout tag against the APAC configuration and corrects its interpretation, recording the original declaration.
The existing `--out decoded` mode writes raw `pcm.f32le` and JSON with a 128 MiB default limit. `-o` and `--out` are mutually exclusive.
Detailed guides are in Chinese. [English quickstart](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/README.en.md) · [Command reference](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/commands.md)

### Support boundaries

- Input must contain APAC audio. MP4/M4A supports unfragmented, single-audio-track files. Ordinary AAC, MP3, FLAC and encrypted/DRM input fail explicitly.
- The CLI exports audio files. HOA coefficients are intended for subsequent spatial rendering.
- DRC, loudness and EQ are parsed as metadata. Decoded output follows this project's numerical model, with documented tolerances for AudioToolbox comparisons.
- LRVQ, outer ASP reconfiguration and nonzero frame-length indices fail explicitly. HOA modes, layouts, sample rates and composite streams must meet their documented configuration conditions.
- Use `decode-sq` for independent decoding. On macOS, `decode`, `replay` and related commands use the system AudioToolbox reference backend. [Full support boundaries](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/blob/v0.2.0/guide/support.md)

When reporting a problem, include the program version, operating system, command and error message, with personal paths removed. [Issues](https://github.com/SakuzyPeng/MacinDecode-APAC-Core/issues)
